# ADR-0001: Tauri 2 as the application shell

- **Status:** Accepted
- **Date:** 2026-10-25

## Context
The UI is a highly custom, animated, macOS-styled window, and we already have an HTML/CSS/JS prototype. We need system access (D-Bus, files) and RPM/AppImage (later .deb) builds.

## Decision
Use Tauri 2: a Rust core and a WebKitGTK 4.1 webview on Linux.

## Consequences
- The prototype carries over almost directly, and we get full design freedom.
- One `tauri build` produces .rpm and AppImage (and .deb later).
- It depends on WebKitGTK 4.1, which is fine on Fedora 44+ and Ubuntu 22.04+.
- The webview can feel slightly less native than GTK4. We mitigate this by following GNOME accent, scheme and button layout ([ADR-0006](0006-window-controls-follow-gnome-layout.md)).
- On GNOME Wayland, undecorated windows get no compositor shadow (see the M0 spike).

## Alternatives considered
Vala + GTK4/libadwaita (most native, but fights a macOS look), Qt/QML (good for custom animation, but foreign on GNOME), Flutter (Linux is a second-tier target), Electron (too heavy). See `docs/handoff/01-conversation-summary.md`.
